# Setup

This repo is `byteforge9190/byteforge9190` — the special repo whose `README.md`
renders on the GitHub profile page. Only `README.md` is shown publicly; every
other file here is scaffolding.

There are four steps and they matter in this order.

## 1. Create the METRICS_TOKEN secret — required

The stats panel is generated by GitHub Actions and committed into this repo as
`metrics.svg`, rather than loaded from a community widget service at page-load
time. That decision was forced: as of the last check,
`github-readme-stats.vercel.app` returns `503 DEPLOYMENT_PAUSED`,
`github-profile-trophy.vercel.app` returns `402 Payment required`, and
`github-profile-summary-cards` serves a card that reads
*"Cards are temporarily rate limited."* Free Vercel deployments run out of money.

Rendering it yourself needs a classic PAT, because the Actions-provided
`GITHUB_TOKEN` cannot read the cross-repo data the plugins want.

1. <https://github.com/settings/tokens> → **Generate new token (classic)**
2. Scopes: `public_repo` — add `read:user` too if you want the habits plugin to
   count private activity
3. Copy the token, then go to
   `Settings → Secrets and variables → Actions → New repository secret`
4. Name it exactly `METRICS_TOKEN`, paste, save

Until this secret exists, `metrics.yml` skips with a warning instead of failing,
and `metrics.svg` stays a broken image in the README.

## 2. Turn on Actions write access

`Settings → Actions → General → Workflow permissions` → **Read and write
permissions** → Save.

Without this the workflows cannot push what they generate, and all three
generated images stay broken.

## 3. Fill in the placeholders

```bash
grep -n REPLACE_ME README.md
```

Six links: email, Telegram, LinkedIn, Discord, X, website. Delete the badges you
do not want rather than leaving dead links.

While you are in there, check the headline numbers in the badge row
(`40+ books`, `<250ms p95`) and the **Featured work** table actually match what
you can talk through in an interview.

## 4. Push, then let the workflows run

The README points at three images that do not exist until Actions has run once:

| Image | Produced by | Lands at |
|---|---|---|
| Stats panel | `.github/workflows/metrics.yml` | `main` → `metrics.svg` |
| 3D calendar | `.github/workflows/profile-3d.yml` | `main` → `profile-3d-contrib/*.svg` |
| Contribution snake | `.github/workflows/snake.yml` | `output` branch → `snake.svg`, `snake-dark.svg` |

All three trigger on push to `main`, so they start themselves after the first
push. To run one by hand: `Actions` tab → pick the workflow → **Run workflow**.
Give them a couple of minutes, then hard-refresh your profile.

The push triggers use `paths-ignore` on the files the workflows themselves
commit. That matters: `metrics.yml` commits with your PAT, and unlike the
built-in `GITHUB_TOKEN`, a PAT push *does* re-trigger workflows — without the
guard it would loop forever.

## Light and dark

The streak card, the snake and the 3D calendar use `<picture>` with
`prefers-color-scheme`, so they stay legible in both GitHub themes instead of a
dark card floating in a light page. If you edit one of those URLs, edit **both**
the `<source srcset>` and the `<img src>`.

The Mermaid diagram uses light fills with dark text for the same reason — that
combination reads correctly under GitHub's dark theme too.
